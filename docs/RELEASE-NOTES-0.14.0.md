# ScopePilot Fork 0.14.0

0.13.0から、探索の通信保存・操作制御・候補レビュー・診断ツールへの引き渡しを改善しました。Fork元は[gsgwr/ScopePilot](https://github.com/gsgwr/ScopePilot)です。BSD-3-Clauseのライセンスと著作権表記を維持します。

## 主な変更

- 取得した要求内容・参照資料・選択ガイドラインを根拠に、診断優先度を0〜100で表示します。採点理由を確認でき、上位N件・N点以上の一括採用に対応します。確信度は判断根拠の明確さとして残します。
- URL・要求本文の処理指定が異なる候補を分けます。候補は1行ずつ表示し、照合できたBurp Proxy historyのネイティブRequest IDを掲載します。
- 「Burp+mcp+AIプロンプト」を引き渡し先へ追加しました。採用したRequest IDを優先度順に並べた文章を表示・コピーできます。この画面からScanやBurpの設定変更は実行しません。
- 「自動実行しない操作」の文章を探索AIが操作前に意味点検します。判断不足・禁止・判断不能の操作は中継で拒否し、判断記録を残します。
- 停止時の正常な捕捉終了、大容量HARの逐次保存、部分結果の回復、リダイレクト補完、完全なブラウザ本文の保持を改善しました。
- 特殊操作は実行履歴の「手動項目を確認」から、対象・理由・必要な確認内容を参照できます。
- PDFに加えて生成PNGをアップロード用に用意し、通常のキーボード操作によるコンボボックス等の操作復旧を案内します。

## 互換性と利用上の注意

実行ファイル名は`ScopePilot.exe`、既存案件は`.scopepilot.json`のままです。この開発環境では`Start-ScopePilot.cmd`から起動します。cloneした環境ではREADMEの依存関係とビルド手順に従ってください。

優先度は診断の順番を決めるための目安であり、脆弱性や安全性の判定ではありません。探索の網羅率100%、全操作の自動実行、禁止操作の誤解釈ゼロ、すべての応答本文の完全取得は保証しません。部分結果・未実行・未照合ID・手動項目を確認してください。通常操作の未確認が残る場合、ログアウト・片付けは自動実行されないことがあります。

Burp IDは接続中のBurp Projectに対応します。Projectを切り替えた場合は再照合してください。テストに使用した案件・認証情報・通信ログはソースへ含めません。

詳しくは[優先度](DIAGNOSTIC-PRIORITY.md)、[禁止操作](FORBIDDEN-ACTIONS.md)、[保存と引き渡しの信頼性](QUALITY-RELIABILITY.md)、[配布手順](../DISTRIBUTION.md)を参照してください。
