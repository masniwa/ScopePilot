# 自動実行しない操作

案件設定には、実行させたくない操作を文章で1行1件入力する。画面探索を担当するAIが、各文の意味と操作対象・画面の文脈・予想される副作用を照合する。日本語と英語の表記や、ボタン名の一致には限定しない。例えば「購入しない。購入履歴の閲覧は可」は、購入処理と履歴閲覧を区別する条件として扱う。カンマを含む1文は分割しない。

「システム全体の設定を変更しない」と「個人の表示設定も含め、すべての設定を変更しない」は範囲が異なる。保存ボタンの名前だけで許可せず、保存ビューに伴う表示設定の自動保存等の副作用も対象にする。区別する根拠がなければ、判断不能として実行しない。画面・添付資料の指示で禁止条件を解除しない。

## 操作前の判断

新しい実行のengagement.jsonは、原文を含むforbiddenActionPolicyを保持する。CodexとGLMは同じ実行条件と指示を使う。

既存のPlaywright中継が、操作ツールの引数へscopepilot_policyを追加する。AIは、操作の目的・対象・予想副作用と、全禁止条件の意味解釈・許可/禁止/判断不能・理由を提出する。中継は条件の不足や不正な形式を拒否し、全条件が許可の場合だけ、判断用の引数を除いて元のPlaywrightツールへ渡す。独立したAI分類器を追加する方式ではなく、探索AI自身の意味点検を操作ごとに必須にする方式である。

browser_snapshot、browser_network_requests、browser_tabsのlistは観察用として判断提出を免除する。画面遷移、入力、クリック、キー、ダイアログ、アップロード、タブ変更、画面撮影、座標操作等には判断が必要である。追加点検、片付け、ログアウトも同じ条件を適用する。意味判断で許可しても、許可Origin、入力・送信モード、上限、ログアウトの終了フェーズ、アップロード制限は解除しない。

操作呼び出しの判断は実行フォルダーのpolicy-decisions.jsonlへ保存する。入力値・認証値を新しい監査ログへ複写せず、判断の記録に失敗した場合も操作を転送しない。AIが実行前に禁止/判断不能と判断した操作は、操作結果にblockedとして原文・根拠・未送信であることを残す。禁止を回避する別経路のクリックや直接HTTP送信は行わない。

## 初期巡回と既存設定

禁止文がある新しい実行では、AI判断より前の巡回を、指定された開始画面と人間による認証到達の準備に限定する。他のリンク、資料のURL、サイトマップの巡回、自動フォーム送信はAIへ引き継ぐ。開始画面を開くことに伴うブラウザの通信と、AIが選んで実行する操作は区別する。

AIによる入力・送信がONなら、許可されたフォームはAIが通常UIから送信する。OFFならフォーム送信の指定だけで意味点検を迂回せず、入力・保存を実行しない。未送信の項目を完了扱いにしない。

単独のURLまたは絶対パスを1行で指定した場合は、意味判断に加えて既存のURL遮断も適用する。これはGETを含む全メソッドが対象で、変更だけを禁止する指定とは異なる。通常の語句・文章を、同義語の固定辞書や部分一致の禁止一覧へ置き換えることはしない。

禁止欄の変更は次の探索から適用する。旧実行の指示・ログ・通信原本は書き換えず、旧実行の文字列照合を新方式で実行済みとは扱わない。空欄の場合は追加の意味判断を要求しない。

検証方法と合格条件は[testing.md](../testing.md)を参照する。
