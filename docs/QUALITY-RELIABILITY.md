# 探索の保存・終了・引き渡しの信頼性

## 保存段階と部分結果

ブラウザHAR、追記型通信台帳、NetLogを原本として扱う。HARの読込・書出しは全体を単一のJSON文字列にせず、逐次処理する。書出しは一時ファイルを同期してから置換し、失敗時に既存のHARを壊さない。解析後のオブジェクト保持メモリーは内容量に比例するため、無制限の容量を保証するものではない。

ブラウザ段階の件数監査と、NetLog補完後の保存・監査は別段階である。補完開始で旧監査を未完了化し、失敗時は失敗段階を記録する。最終HARのハッシュ・サイズと通信台帳のサイズを、wire完了サマリーと最終監査の両方で照合する。件数一致は本文の完全受信や業務処理の成功を証明しない。本文制約・終端未確認があれば部分結果を維持する。

NetLog本文が不完全でも、同じブラウザ要求イベントで保存した本文について、終了記録・HTTP状態・Content-Length・保存長・SHA-256・取得済みNetLog本文との先頭一致を確認できる場合は、完全なブラウザ本文を保持する。圧縮応答や別イベント・ヘッダー不一致・本文不一致を推測で補完しない。採用した本文の出典とNetLog側の部分本文・エラーを併記し、元の記録を保持する。NetLog自身の本文エラー件数と、補完後にも残る本文エラー件数を区別する。

最終HAR保存に失敗しても、有効なbrowser-capture.harを使い、要求本文・処理指定・要求フィンガープリントを部分結果へ回復する。原本を書き換えて成功扱いにせず、候補再計算でも部分状態を維持する。案件を開くときも、直近の通信保存が未完なら部分結果を表示する。

## 認証と要求の出典

ログイン待ちから認証後の到達確認までは、通信の認証状態を未確認として記録する。手動の再開確認より前の通信を、匿名アクセス成功と解釈しない。認証状態の変更は時刻とロールを記録し、集約時は時刻順で適用する。未確認ロールは複数ロール加点へ使わない。古い原本の不確実な認証状態を、根拠なく認証済みへ補正しない。

要求のフィンガープリントを更新するときは、対応する要求時刻とProxy IDの出典も一緒に更新する。別の送信イベントに変わった場合は古いIDを無効化する。Burp履歴では同じ内容の要求を全ページから探し、観測時刻に最も近いものを選ぶ。内容一致と、同一送信イベントの確定は区別する。

## 終了判定と操作報告

許可Origin外の実リンクを送信しなかった操作は、blockedのまま残す。新しいAI報告はboundaryへ観測URLとUI出典を構造化して返し、制御側が実際の案件Originと比較する。説明文だけの「範囲外」を完了条件へ使わない。旧報告では実リンク先と明示的な境界判断があるものを互換処理し、実URLが案件内なら外部扱いにしない。

範囲外・手動・確認済みの分類は、独立棚卸しを省略する理由にしない。通常未実行が残れば終了処理へ進まない。境界を正しく処理してキューが解消した場合だけ、既存の上限と禁止操作を維持して片付け・許可済みログアウトへ進む。

操作報告のrequestsが空の場合、HTTPなしを明示した操作と、通信との対応が未照合の操作を区別する。operation-evidence-review.jsonはこの区別を記録し、未照合をHTTPなし・送信成功へ推定しない。要求参照の記載も独立した通信照合の完了とは扱わない。

PDF等はダウンロードイベントを根拠に、開始・完了・失敗をHTML遷移の一般エラーと分ける。ブラウザのダウンロード完了と、HTTP本文の保存完全性は別に確認する。

## 資料と診断ツールへの引き渡し

資料の相対エンドポイントは元表記・出典・解決方法を保持する。root相対パスを補完できるのは許可Originが一意の場合だけで、補完は文書由来の推定と明示する。未解決相対パスやIDテンプレートを巡回しない。テンプレートは実際に観測した通信との対応付けに使えるが、未観測要求を作らない。

Burp Scopeはパスの大文字小文字を保持し、IDプレースホルダーと末尾スラッシュに対応する。生成した正規表現が全採用代表URLへ一致することを出力前に検査する。旧案件の小文字パターンと手動判断は、対応する代表通信の範囲だけ読み込み時に移行し、元案件を自動保存しない。

ZAPは正式登録されたHARを使う。混在ロールのHARは、各entryに捕捉ロールがある場合だけ現在のロールと一致する通信を選ぶ。ロール未記録の混在通信や、未登録ブラウザ原本を一律の認証ロールとして使わない。一致通信が0件なら診断用HAR・実行計画を準備済みと表示しない。API下書きとWeb探索の案内を分ける。

プロンプト方式は採用IDから文章を作成・コピーするだけで、Scanや設定変更を実行しない。案件切替時は以前のBurp履歴照合の成功文を消し、個別採用変更でも採用件数を即座に更新する。
